# Local Dominate — Current Reality (2026-09-30)

Companion to `TAKEOVER_AUDIT.md` (2026-09-27), `ARCHITECTURE.md`, `DEPENDENCIES.md`, and
`LOVABLE_DEPENDENCY_AUDIT.md` / `LOVABLE_EXIT_PLAN.md` (2026-09-29, branch
`rebrand/localdominate-2.0-foundation`, not yet merged). Those documents describe the
architecture as it stood on their respective dates and are **not rewritten** here — this
document is the current-state addendum. Where this document and an older one disagree, this
one is current.

**Do not read this as "Lovable exit complete."** Hosting independence is complete. Backend
independence is not. See §2.

## 1. What changed since 2026-09-29

### COMPLETED (2026-09-30)

- **Netlify hosting migration.** Production build (`npm run build:static` + `scripts/prerender.mjs`)
  deploys to Netlify project `strong-cascaron-e33b5a`. Verified live: `/`, `/campsites`,
  `/campsites/`, `/blog/local-seo-anwaelte-kanzleien` all return `200`, no redirects (the earlier
  "Pretty URLs" auto-redirect bug is fixed — disabled in Netlify settings + redeployed).
- **DNS.** `localdominate.org` A record repointed at IONOS from Lovable's `185.158.133.1` to
  Netlify's `75.2.60.5`; `www` changed from an A record to a `CNAME` → `apex-loadbalancer.netlify.com`.
  Netlify's domain verification for both `localdominate.org` and `www.localdominate.org` succeeded
  (screenshot-verified, "DNS verification was successful").
- **SSL.** Netlify's automatic Let's Encrypt certificate provisioning was triggered by the DNS
  verification; issuance is in progress (normal — can take minutes to ~24h). Not yet independently
  re-verified as issued at the time of writing.
- **Lovable build artefacts removed** (done 2026-09-29 on `rebrand/localdominate-2.0-foundation`,
  **not yet on `main`**): `bun.lock`, `bun.lockb`, `.lovable/` (moved to
  `docs/archive/lovable-planning/`), `lovable-tagger` devDependency, `previewAuthStorage.ts`,
  admin Google OAuth swapped from `@lovable.dev/cloud-auth-js` to native Supabase
  `signInWithOAuth`. These changes are real but **live only on that unmerged branch** — `main`
  (and therefore production) still has the original Lovable packages/files as of this writing.
- **Netlify SPA fallback + build config** (`netlify.toml`, merged to `main` 2026-09-28): confirms
  the app builds and serves correctly outside Lovable.

### STILL ACTIVE (unchanged, real runtime dependency)

- **Lovable Cloud Supabase** (project `minijgyozgjuhqgkmilj`) is still the live database, auth
  and storage backend. ~7,370 rows including customer/lead/questionnaire PII have **not** been
  migrated to an independent Supabase project. This is the same project, same data, same
  ownership question as in `TAKEOVER_AUDIT.md` §1 and §5 (R4).
- **19 Supabase Edge Functions** still run under that same Lovable Cloud project — including
  `stripe-webhook`, which handles **live payments**. None have been redeployed elsewhere.
- **`LOVABLE_API_KEY`** dependency for `generate-ai-audit-report` (calls Lovable's AI gateway) —
  unchanged, still required for that one feature to work.
- **Google admin OAuth broker** (`@lovable.dev/cloud-auth-js`) — unchanged **on `main`**. A fix
  exists on the unmerged `rebrand/localdominate-2.0-foundation` branch but has not shipped to
  production.
- **7 cron jobs** configured inside Lovable Cloud (not in this repo) — unchanged, still running
  wherever Lovable Cloud runs them.
- **Lovable Git auto-sync status is unverified** — see `LOVABLE_SYNC_VERIFICATION.md` (new,
  this batch). This is the hard gate before any long-lived redesign branch.

## 2. Net assessment

| Layer | Independence status |
|---|---|
| Hosting (serving the site to visitors and crawlers) | **Independent.** Netlify, DNS repointed, SSL provisioning. |
| Build pipeline | **Independent.** `npm install` + `npm run build` / `build:static` work without Lovable; CI (`checks.yml`) already runs on GitHub Actions. |
| Frontend code / source of truth | **Independent** (GitHub, has been since `main` was seeded 2026-09-27). |
| Backend (DB, auth, storage, edge functions, payments) | **Not independent.** Fully on Lovable Cloud, unchanged. |
| Admin login | **Not independent on `main`** (fixed only on an unmerged branch). |
| AI audit feature | **Not independent** (`LOVABLE_API_KEY`). |
| Git repository control (auto-sync) | **Unverified** — cannot claim either way without a manual dashboard check. |

**Conclusion: do not describe the Lovable exit as complete, in any document, until §2's "Not
independent" and "Unverified" rows are closed.** Hosting migration was the highest-visibility
risk (R1/R2 in `TAKEOVER_AUDIT.md`) and it is genuinely closed. The remaining risks (R4–R7, R15)
are unchanged.
